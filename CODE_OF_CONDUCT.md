# CODE_OF_CONDUCT.md — Collaboration rules for parallel agents

Multiple autonomous agents push to this repository at the same time. Most merge pain comes from
agents not respecting boundaries, not from technical conflicts. These rules exist to make parallel
work boring.

---

## 1. Ownership

- A workspace `agent_<slug>/` belongs to **exactly one** agent identity for its lifetime.
- You may create new packages inside your own workspace. You may not create, edit, move, rename, or
  delete anything inside another agent's workspace.
- You may not edit shared infrastructure (`README.md`, `AGENTS.md`, `STANDARDS.md`, `CONTRIBUTING.md`,
  `docs/`, `templates/`, `tools/`, `.github/`, `LICENSE`). If you believe something there is wrong,
  open an issue or a **separate** PR with a clear explanation.
- The root `README.md` model index is generated by tooling. Do not hand-edit the
  `<!-- MODELS:START --> … <!-- MODELS:END -->` block.

## 2. Gitting

- Stage explicitly: `git add agent_<slug>`. **Never** `git add -A` or `git add .` at repo root.
- **Never** force-push. **Never** rebase or amend commits authored by someone else.
- **Never** push to `main` unless the repo owner has explicitly asked you to for that action.
  Prefer a branch + PR, always, because CI runs there.
- One package (or one coherent milestone) per PR. Bundle nothing unrelated.
- If you find yourself needing to resolve a conflict outside your own workspace, stop and re-apply
  only your files instead.

## 3. Truthfulness

- Report the model you actually shipped. Limitations sections exist to be used.
- Do not claim a render is "inspected" if you didn't open it.
- Do not invent triangle counts, dimensions, or references.
- Do not mark the self-review checklist complete if any item is untrue. A dishonest tick is treated
  as a failed PR, and repeat behaviour gets the workspace frozen.

## 4. Originality and respect

- Author your own geometry. No scraped meshes, no converted asset-store downloads, no AI-generated
  meshes.
- No identifiable copyrighted characters, logos, or trademarked designs. Generic forms in the spirit
  of a style are fine; replicas of someone's IP are not.
- Credit any external licensed resource (e.g. CC0 HDRI) in the package README.

## 5. Review etiquette

- Critique the work, not the agent. Be specific: "the bail handle intersects the collar at the top
  hinge" beats "geometry is bad".
- If you review someone's PR and it's non-compliant, say which rule and where. Don't silently fix
  their files.
- If you disagree with a standard, argue for changing the standard — in an issue — not by quietly
  ignoring it in your own PR.

## 6. Cleanliness

- Don't leave rejected renders, caches, or scratch scripts committed. Workspaces are the public
  face of this repo.
- Don't commit secrets. Your push token never goes into a file in this repository. If you
  accidentally commit a secret, say so immediately in the PR/issue — it must be rotated.
- Respect the size caps (60 MB/file, 80 MB zip). Huge blobs are effectively permanent in git history.

## 7. Escalation

Escalate to a human (PR comment or issue) only when:
- you cannot push or CI is broken for reasons outside your change,
- the instruction you received conflicts with these docs,
- the asset would require third-party licensed data.

Do not escalate for ordinary design decisions: colour, detail level, style, camera choice, or
scope. Decide, document, move on.
